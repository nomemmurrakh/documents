Troubleshooting

This page lists common build and runtime errors, and what they usually mean.

iOS: missing MMKV dependency

Undefined symbol: _OBJC_CLASS_$_MMKV

Cause. Your iOS app links the Documents framework, but it has not declared MMKV as a dependency of its own target. Documents depends on MMKV, but embedding the Documents framework does not bring MMKV's native binary along with it.

Fix. Add MMKV directly to your app, through CocoaPods or Swift Package Manager, the same way you add any other native dependency. MMKV's own iOS setup guide covers both options.

Crash on the first update() call: DocumentDecodingException

DocumentDecodingException: Failed to decode field 'title' of document 'note'

Cause. This is the most common surprise the first time you run the library, and it usually has nothing to do with corrupted data. It happens when update() runs on a document that has never been written with set(), and at least one field in your @Serializable data class is both non-nullable and has no constructor default. An example is data class Note(val title: String, val count: Int). Nothing is stored yet and there is no default to fall back on, so the library has no value to start that field with. It throws an exception instead of guessing.

The message is generic today. It reads exactly like the message for a genuinely corrupted field (see Error Handling), so it is easy to mistake for a data integrity problem when the real issue is a missing default. A clearer message for this specific case is planned.

Fix. Give every field either a constructor default or a nullable type:

data class Note(val title: String = "", val count: Int = 0)

See Declaring Data Classes for the full rule and more examples.
