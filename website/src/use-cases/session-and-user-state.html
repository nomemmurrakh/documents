Session & User State

Session state is the signed-in user, an auth token, and the active profile. It belongs to a login session, not to the app's long-lived settings. Keep it in its own collection so it stays separate from data that should survive a logout.

@Serializable
data class Session(
    val userId: String,
    val displayName: String,
    val authToken: String,
)

val sessionStore = Documents.collection("session")
val session = sessionStore.document<Session>("current")

// sign in
session.set(Session(userId = "u_42", displayName = "Mara", authToken = "…"))

// react to sign-in / sign-out anywhere in the UI
session.flow().collect { current ->
    isSignedIn = current != null
}

Signing out means deleting the session document. The public API has no "clear the whole collection" call, so sign-out is an explicit delete() on each document that should end with the session:

fun signOut() {
    session.delete()
}

Encrypting the auth token

The authToken is a good candidate for field-level encryption, and the session collection is a natural encryption boundary. FieldDecorator is the extension point for this. The example below uses cryptography-kotlin (dev.whyoleg.cryptography, v0.6.0). It is one choice among several, and your app adds it as a dependency. Documents does not pull it in:

// build.gradle.kts (your app/module, not Documents itself)
implementation("dev.whyoleg.cryptography:cryptography-core:0.6.0")
implementation("dev.whyoleg.cryptography:cryptography-provider-optimal:0.6.0")
import dev.whyoleg.cryptography.CryptographyProvider
import dev.whyoleg.cryptography.algorithms.AES

class AesGcmFieldDecorator(
    private val key: AES.GCM.Key,
) : FieldDecorator {

    private val cipher = key.cipher()

    override fun wrap(fieldName: String, bytes: ByteArray): ByteArray =
        cipher.encryptBlocking(
            plaintext = bytes,
            associatedData = fieldName.encodeToByteArray(),
        )

    override fun unwrap(fieldName: String, bytes: ByteArray): ByteArray =
        cipher.decryptBlocking(
            ciphertext = bytes,
            associatedData = fieldName.encodeToByteArray(),
        )
}

val provider = CryptographyProvider.Default
val key = provider.get(AES.GCM).keyGenerator().generateKeyBlocking()

val sessionStore = Documents.collection("session") {
    decorators = listOf(AesGcmFieldDecorator(key))
}
val session = sessionStore.document<Session>("current")

A few details in this example are worth knowing:

  • Blocking calls. The example uses encryptBlocking and decryptBlocking, not the suspending encrypt and decrypt, because FieldDecorator.wrap and unwrap are synchronous.
  • Tamper detection. encryptBlocking puts the nonce and the authentication tag into the returned ByteArray. If a stored value is tampered with or corrupted, AES-GCM detects it instead of decoding garbage.
  • Associated data. Passing fieldName as associated data means a ciphertext copied from one field's key to another fails to decrypt. It does not silently succeed with the wrong data.
  • Keys are your job. Your app is responsible for generating, storing, and rotating keys. The cryptography-kotlin docs cover that part.

To see how the extension point itself works, read Decorations and Field Decorators.
