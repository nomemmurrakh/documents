Reactive UI State

Reactive UI state is any state that Compose or SwiftUI should re-render when it changes. A document's flow() gives your UI layer exactly that, with no manual re-reads and no polling.

@Serializable
data class DownloadState(
    val bytesDownloaded: Long = 0,
    val totalBytes: Long = 0,
    val isComplete: Boolean = false,
)

val download = Documents.document<DownloadState>("active-download")

A background worker updates bytesDownloaded as chunks arrive. This is a single field, so update(prop, value) is the natural fit. It makes one direct write to that key:

download.update(DownloadState::bytesDownloaded, bytesSoFar)

A Compose screen collects the same document and redraws on every write. It does not need to know where the write came from. The screen can even hold a different instance of the document than the worker does, and it still sees every write:

@Composable
fun DownloadProgressBar(download: Document<DownloadState>) {
    val state by download.flow().collectAsStateWithLifecycle(initialValue = download.get())
    val progress = state?.let { it.bytesDownloaded.toFloat() / it.totalBytes } ?: 0f

    LinearProgressIndicator(progress = progress)
}

The sample app shows this pattern from start to finish. A button press writes to a document, and a separate readout re-renders only because it collects the document's flow(). See Reactivity for the full flow() and stateFlow() API.
