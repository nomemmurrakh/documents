Caches & Drafts

Caches and drafts include the last synced payload, an in-progress form, and the "continue where you left off" data. This data is useful but disposable. Keep it apart from durable settings, so it is easy to reason about and easy to wipe on its own.

@Serializable
data class SyncState(
    val lastSyncedAtEpochMs: Long = 0,
    val lastSyncedEtag: String = "",
)

@Serializable
data class DraftPost(
    val title: String = "",
    val body: String = "",
)

val cache = Documents.collection("cache")

val syncState = cache.document<SyncState>("sync-state")
val draft = cache.document<DraftPost>("compose-draft")

The compose screen writes to draft after each debounced keystroke. On the next launch it reads the draft back, so the user continues exactly where they left off:

draft.update { current ->
    current.copy(body = textField.value)
}

// next launch
val restored = draft.get() ?: DraftPost()

cache is its own collection, which means it has its own MMKV file. If you reset it, for example from a "reset cache" action or a storage cleanup, by deleting its documents, the durable data in the default store or in another collection is not touched. See Collections & Testing for how collections keep one set of documents separate from another.
