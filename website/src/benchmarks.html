Benchmarks

Documents splits a value into one {doc}::{field} key per field, and it runs a CBOR encode and decode for each field. These microbenchmarks measure the cost of that work against using raw MMKV directly. The raw baseline encodes the same 5-field value once with CBOR and calls MMKV's byte API.

Sample type:

@Serializable
data class Profile(
    val id: Long,
    val name: String,
    val email: String,
    val age: Int,
    val active: Boolean,
)

Methodology

Each raw MMKV baseline does the same underlying work as the Documents call it is paired with. It uses the same field keys, the same per-field CBOR encode and decode calls, the same existence prefix scan before a read, and the same prefix scan and remove on clear. It does all of this by hand, with no library machinery: no lock, no change bus, and no composite encoder. That isolates what the abstraction costs on top of doing the identical raw operations manually.

The comparison does not pit Documents' per-field storage against a single whole-object blob, because that would be an unfair comparison.

The numbers are captured on a device or simulator. This is not a JVM host benchmark, because MMKV is memory-mapped and needs a real device or simulator. The numbers depend on the device and OS, they are illustrative and not authoritative, and they are not run in CI.

How to read the table:

  • Whole-object update { }. The builder always does a full 5-field get followed by a full 5-field set, even when only one field changed. This is the read-modify-write path. The raw baseline repeats that same round trip instead of a hand-tuned single-key patch, so the pairing stays honest.
  • update(prop, value). This is a true single-key write with no read. It is even cheaper than a field delegate write, because it skips the ReadWriteProperty object that the delegate allocates.
  • delete. This measures a set followed by a delete.
  • Absolute timings. They come from a simulator, so they reflect the host CPU and not real hardware. Compare Documents with raw MMKV within this table, and not against other platforms.
