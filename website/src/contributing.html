Contributing

Issues, pull requests, and stars all help. The project lives at github.com/nomemmurrakh/documents and is licensed under the Apache License 2.0.

What a pull request has to pass

Every pull request runs through CI, which checks three things:

  • Build and test. iosSimulatorArm64Test runs on macOS, and testAndroidHostTest runs on Ubuntu.
  • ABI check. :documents:checkKotlinAbi guards the public binary surface.
  • Static analysis. detekt checks the Kotlin code.

Proposing a design change

Significant design decisions are recorded as Architecture Decision Records (ADRs) in docs/adr. To propose a new decision:

  1. Open an issue or a pull request that describes the change and why it is needed.
  2. Add an ADR file to docs/adr. Name it with the next number in the sequence and a short title, for example 0023-short-title.md.
  3. Write it in the same shape as the existing ADRs, with a status, a date, the context, the decision, its consequences, and the alternatives you considered.
  4. Add a row for it to the table in docs/adr/README.md.

ADRs are numbered in order and are never renumbered or deleted. If a new ADR replaces an older one, the older one stays where it is, and its status is updated to point to the new one.

Where to start

Read the Guide and Design Decisions to see how the library is built and why. Then open an issue or a pull request on GitHub.
