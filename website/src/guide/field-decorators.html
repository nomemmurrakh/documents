Field Decorators

A FieldDecorator lets you hook into the read and write path of a document, one field at a time. It can wrap a field's bytes before they reach storage, and unwrap them when they come back. Use it for per-field encryption, compression, checksums, or logging.

Attaching decorators

You can configure decorators on a collection, on a document, or on both:

val notes = Documents.collection("notes") {
    decorators = listOf(LoggingDecorator())
}

val note = notes.document<Note>("note-1") {
    decorators = listOf(ChecksumDecorator())
}
// note's effective decorator list, in order: [LoggingDecorator(), ChecksumDecorator()]

Decorators on a collection apply to every document opened in that collection. Decorators on a document are added after them, for that document only.

Order matters

On a write, the bytes pass through the decorator list from left to right. On a read, they pass through it from right to left. The decorator that ran last on write runs first on read, so each wrap is undone in the reverse of the order it was applied:

// decorators = listOf(Compress, Encrypt)
// write:  bytes  -> Compress.wrap   -> Encrypt.wrap   -> stored
// read:   stored -> Encrypt.unwrap  -> Compress.unwrap -> bytes

This is why you should compress first and encrypt second, and not the other way around. Encrypted bytes look random, so they do not compress in any useful way. See Decorations for why the library applies the list in this order.
