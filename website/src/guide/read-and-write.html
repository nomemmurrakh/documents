Read & Write

There are three ways to write a document, and each has a different purpose. Knowing which one to use is the main thing to learn about this API.

note.get(): Note?                       // current value, or null if absent
note.set(value)                         // replace the whole document
note.update { current -> ... }          // build a new value from the current one (or the defaults)
note.update(Note::done, true)           // single-field update: writes just that key, no read
note.delete()                           // remove the document and all its field keys
note.exists(): Boolean                  // true if any field key is stored

get(): read the document

get() returns the current value, or null if the document has never been written. A missing document is not an error:

val current: Note? = note.get()

set(value): replace the document

Pass a complete object and it replaces the whole document, including every field whether it changed or not:

note.set(Note(title = "Pick up milk", body = "2%, not whole"))

update { current -> ... }: change several fields

The builder receives the current value as the current parameter and returns a new value built with copy(). If the document has not been written yet, current holds the type's defaults. This has the same shape as MutableStateFlow.update { current -> ... } in kotlinx.coroutines. Fields you do not touch keep the value they had:

note.update { current ->
    current.copy(
        title = "Pick up oat milk",
        body = "The barista-approved kind",
    )
}

This reads and then writes while holding the document's write lock. A multi-field update is therefore atomic, and a concurrent reader never sees a half-applied write.

update(prop, value): change one field

When only one field needs to change, update(prop, value) writes just that field directly. It does not read the rest of the document:

note.update(Note::done, true)

Choose between the two forms of update like this:

  • Use update(prop, value) when you change exactly one field and the new value does not depend on the current one.
  • Use update { current -> ... } when an edit touches more than one field together, or when the new value depends on the current one.

delete() and exists()

note.delete()            // removes the document and all its field keys
println(note.exists())   // false
