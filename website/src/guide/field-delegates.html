Field Delegates

Sometimes you do not need the whole document. You only want one field, read and written like an ordinary Kotlin property. Field delegates give you that while keeping the storage typed and reactive.

class NoteEditor {
    private val note = Documents.document<Note>("note-1")

    var done: Boolean by note.field(Note::done, default = false)
    val doneFlow: Flow<Boolean> = note.fieldFlow(Note::done, default = false)
}

field(prop, default)

field(prop, default) returns a ReadWriteProperty that is backed by a single stored key. Reading it returns default if the field was never set. Writing it updates only that field's key and leaves the rest of the document alone. A write also emits on the document's flow():

editor.done = true   // writes only the "done" field's key
println(editor.done) // reads only that key

Why you supply default

A property's declared default value cannot be recovered from a KProperty at runtime. Once you hold a bare property reference, there is no way to ask what default the data class gave it. So field() and fieldFlow() both take default as an explicit argument.

fieldFlow(prop, default)

On collection, fieldFlow emits the current field value, or default if the field was never set. After that it emits a new value each time that field changes. A change to a sibling field does not trigger it:

note.fieldFlow(Note::done, default = false).collect { done ->
    checkbox.setChecked(done)
}

Without a delegate: update(prop, value)

If you only need a one-off write to a field and have no property to declare, call note.update(Note::done, true). It does the same single-key write directly. See Read & Write. Use it in code that does not own a var property backed by the field.

Decorators apply here too

field() and fieldFlow() read and write through the same internal path as update(prop, value), so any configured FieldDecorators run here as well. See Field Decorators.

When to use this

Field delegates suit settings-style code: a screen with a handful of independent toggles or values, each bound directly to a property, where you never need to read or write the rest of the document. See Settings & Preferences for a fuller example.
