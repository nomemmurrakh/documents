Collections & Testing

Collections

A Collection is a named, separate MMKV file. Use one when a group of documents needs its own lifecycle or boundary. Typical reasons are a cache that is wiped on logout, data scoped to one user, or an encryption boundary. See Opening Documents for how to open one.

Testing with an in-memory backend

Documents.inMemory() returns a Collection that behaves the same way but keeps its data in memory instead of a real MMKV file. You need no device and no simulator, and there is no disk state to clean up between tests. Each call to Documents.inMemory() returns its own isolated store, so tests never leak state into each other:

val store = Documents.inMemory()
val note = store.document<Note>("note-1")

note.set(Note(title = "Test note"))
assertEquals("Test note", note.get()?.title)

One process only

Every store can only be used from one process. This applies to the default store, every named collection, and the in-memory backend. See the Overview for the details.
