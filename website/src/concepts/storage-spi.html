Storage SPI

Under the public API there is a small interface that makes the storage engine swappable. It describes how the library is built. It is not something you implement or configure yourself.

internal interface Storage {
    fun getBytes(key: String): ByteArray?
    fun putBytes(key: String, value: ByteArray)
    fun remove(key: String)
    fun contains(key: String): Boolean
    fun keys(prefix: String): List<String>
}

Every stored field key (see Field Decomposition) is read and written through these five operations. There are two implementations:

  • MmkvStorage wraps a real Tencent MMKV instance. It is used in production on both Android and iOS.
  • InMemoryStorage wraps a plain in-memory map that is safe for concurrent access. It backs Documents.inMemory(), which is used for unit tests that need no real MMKV instance. See Collections & Testing.

Everything above this interface lives in commonMain. That includes the public API, field decomposition, serialization, and reactivity. None of it knows which Storage implementation it is talking to.

Only the concrete implementation is platform-specific, and that is what keeps the public surface identical across platforms. See Shared KMP Persistence and Platform Support.
