Serialization (CBOR)

The library uses a single internal CBOR format. It sits between the field walker and the storage layer, and it encodes each field value directly to bytes. There is no JSON text and no intermediate string.

// conceptually, per field:
val bytes: ByteArray = cbor.encodeToByteArray(serializer, fieldValue)
storage.putBytes("note-1::title", bytes)

Not a pluggable extension point

The format is an internal detail, not a setting you can change. The on-disk format is not configurable in v1.

Why CBOR, not JSON

CBOR encodes straight to compact binary. There is no text to produce and no string to parse back, so the format stays small and encoding and decoding stay cheap, on top of a storage engine that is already memory-mapped.

Each field is encoded on its own (see Field Decomposition), so the format only ever has to represent one field's value at a time, never a whole document.

If you configure a decoration, it runs right next to this step. It wraps the encoded bytes just after encoding, and unwraps them just before decoding.
